# Repository workflow

- Before changing code, inspect `git status`, fetch the remote, review incoming commits, and pull/rebase safely without discarding local or collaborator changes.
- Review unfinished local work and failed or missing deployment steps before starting a new request.
- Preserve user data and recovery artifacts. Never replace formula-driven portfolio calculations with hardcoded screenshot totals.
- For portfolio changes, run the relevant tests, full test suite, lint, and production build. When the requested change is for the live site, finish and verify the Firebase deployment.
